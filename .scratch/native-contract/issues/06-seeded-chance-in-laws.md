# 06: Seeded chance in the laws: streams, hazards, forcing

Spec: [First build slice](../../../docs/architecture/solver-contract.md#first-build-slice-spec)

**What to build:** A law declares a stream and a hazard guard that fires a mode change when the integrated hazard crosses the stream's draw, and a forcing that varies a rate on a knotted spline; replay holds with both on.

Blocked by: 05

Status: resolved

- [x] The stream's draw depends only on seed, key and event ordinal: adding a second stream leaves the first's draws unchanged
- [x] A forced extra evaluation before the hazard event leaves its draw and ordinal unchanged
- [x] Two step policies give the same event time to the replay tolerance, and a must-fail core that draws per step is rejected
- [x] Admission holds the forcing at its mean; every replay gate in ticket 05 passes with the stream and the forcing on

## Answer

A law now declares a stream, a hazard guard and a forcing by reference, and each declaration records what it owes: compile refuses a stream no guard draws on, a second guard on one stream or one integral, and a forcing no law reads. A draw is a keyed mixer over seed, key and event ordinal. A hazard integral is a memory row that only rises, because the contract integrates the positive part of its rate, so one comparison on a published state says whether a guard crossed. The contract finds the crossing by solving ordinary shorter tickets, and it does this before it reads any waiting input. A core learns nothing new and `CoupledSolver` does not change. Modes and stream ordinals moved into `Candidate`, so every seal covers them and `StreamPositions` is gone. The walk's step 1c and the sketch's probe at line 457 are lifted.

- **A draw depends only on seed, key and ordinal.** `a_draw_is_a_function_of_seed_key_and_ordinal_whatever_else_fires` holds it across two bodies that fire differently, and `a_refusal_discards_the_reset_the_advance_and_the_mode_together` shows a refused step moves no digest, so no ordinal. `adding_a_second_stream_leaves_the_first_streams_events_unchanged` compares every bit of every event on 24 seeds, because while a landing read every armed guard, a stream that crossed nothing moved another stream's landing on about one seed in six with every draw equal. A landing now reads a guard that crossed.
- **A forced extra evaluation leaves the draw and the ordinal alone.** `SolvesTwice` solves every ticket twice, and the extra-evaluation gate compares each seal and the final digests with a plain run of the same core. A seal covers every mode and ordinal, and a draw is a function of its ordinal. A trial holds no firing: `land` fires the step its bracket closes on, so a dry `verify` shows none, and a step a cut then drops publishes nothing.
- **Two step policies give the same events, and a core that draws per step is rejected.** The step-policy gate compares each policy with a `ReferenceIntegrator` its plan names by type, so two wrong policies cannot certify each other. It pairs events by stream and ordinal, because two unrelated events can share a landing under a coarser policy and come out in another order. `a_core_that_draws_per_step_passes_every_bit_gate_and_fails_the_step_policy_gate` rejects the must-fail core on the fixture, where it was rejected on all 300 seeds tried. A gate's reach is its distance, which its evidence now names: the same core at a third of its tilt passed on 43 of 300 seeds, at a fifteenth on 299, and at full tilt on a grid four times finer on 6. A core that moves events by less than an honest policy's own error cannot be told from one, so the contract's must-fail table states this limit.
- **Admission holds the forcing at its mean, and every gate passes with both on.** Admission reads a forcing as 1 and a draw as 1/2 and takes no seed, so a start state is a function of the packet alone. The gates take `&dyn ReplayCase`, and `every_replay_gate_passes_with_a_stream_and_a_forcing_on` runs all six on `ChanceCase`.

**The fork that decided the shape.** Who locates a crossing. Both candidates found alone that a core should not: a core would learn guards, and the record would have to recheck each claim with the same two tickets, so the check is the search. They then split on the order against a cut. Cutting at the input first broke I5 in at least 110 of 120 random cases, because a run that knows an input past the crossing lands somewhere a run that does not know it never would. So an attempt finds the blind step first, landing included, and only then reads what waits. A cut that crosses lands in turn and keeps the cut's fence, so SRS I5 gains a second way to stop short of an input. Record 0007 extends record 0006 with this.

**Choices, each with its evidence.**

- **Base.** The Opus candidate's implementation with the Codex candidate's seam folded in. The judge, a Codex seat, scored the Codex candidate 20 to 18 and named it as the base. Both agree on the whole shape, the Opus bodies ran on the real crates and the Codex bodies were `todo!()`, and each fork below rests on a probe or a reason a reader can check, not on the score.
- **Firing.** Inside `land`, after the bracket closes, from the judge's finding that a dry `verify` must show no firing. `attempt` reads the timeline only after that, so a firing with no state to publish refuses alike in a run that knows an input and one that does not. Every law is read on what a firing leaves, because the first review pass published a head no law could continue from: `verify` had never read the mode and the zero the firing left. A law with no value there refuses the trial, so the fault falls short of the crossing and names the law. A range is judged on both sides of the instant. The search's state is private to `boundary.rs`, and `attempt` returns what it always did.
- **Landing tolerance.** The core's floor, already in the run identity, so a core declares nothing new.
- **Search.** A secant on one guard's gap with half-tolerance nudges, bisecting on a stall. It pays 2.8 to 6.5 extra solves per landing on the fixture, against 10 to 30 for bisection, over spans of 1 to 16 s and floors of 1 ns to 1 ms. A trial stays a floor from each end of a bracket wider than two floors, and the middle closes a narrower one, so no ticket is shorter than half the floor. A step shorter than the floor ends at its firing, as a cut can end short of the floor at a breakpoint.
- **Which guard a landing reads.** The first that crossed in stable order, and any guard's crossing moves the bracket. Reading every armed guard let a bystander move a landing. Reading one guard's outcome alone fired an earlier guard up to 28 s late, and every gate passed it inside its distance, so `a_landing_stops_at_the_first_crossing_whichever_guard_it_reads` holds this with exact truth: with the forcing flat, a first crossing is a threshold over a rate.
- **Retry of a refused trial (finding 12).** `StepTicket::refuse`, unchanged. A landing's own lengths come from the bracket, which is the retry length a guard needs and which knows the guard. A refused trial is a numerical failure, and it retries by the rule that stays blind inside a cut. A retry at the bracket's bottom crawled an honest core at 1 ns a step, 2,980 refusals in 3,000 steps, because an error estimate over a forcing is not monotone in length: a 64 s span passed where a 32 s trial was refused. This reads the finding's "own retry length" by its purpose.
- **Negative hazard rate.** The contract integrates the positive part. Without it, whether a hump between two published states fires depends on step length, against I8, and a refusal would fault on a seed-dependent dip. A validity range still judges the law's own value, so a rate out of range shows on the receipt.
- **Accrual while disarmed.** The law as declared: a rate holds where its `ModeSet` says. An author who wants a sojourn clock writes a zero law for the other modes, which `UncoveredMode` already forces.
- **Armed past its draw.** Fires within a floor of arming, by the ordinary search.
- **A race on one mode variable.** The first in stable order fires, and the loser did not happen: it keeps its integral and its draw. A guard a firing arms waits for the next step, so a step fires no chain.
- **One integral, one guard.** A reset cannot serve two thresholds. The first design allowed two guards on one integral, and an adversary showed one guard's reset erasing the other's event, so compile refuses it, as both candidates had.
- **Modes and ordinals.** In `Candidate` with a `fired` flag, so `AcceptedStateView::new` and `CoupledProblem::new` keep their signatures. A checkpoint is bound to one model hash, so a list of keys on disk would be a second source of truth.
- **`ModesNotYetRun`.** Lifted only for a mode variable hazard guards alone move, in a body with no algebraic row. A firing leaves algebraic values as they were, and the judge's probe published a residual of -27. Tickets 08 and 10 lift the rest.
- **Forcing.** `1 + a s(t)`: a uniform cubic B-spline over seeded knots, period and amplitude packet values declared by key. A period must be a whole count of nanoseconds, read back through the packet's value, because rounding ran a different period and a test on the product alone refused 1.001 s.
- **Packet checks (finding 15).** `bind` refuses `UnbackedConstant` for `exp` or `logistic` over literals and for a division of two equal nodes, where ticket 08 extends it. The finding names a parameter over itself. A state over itself is the same constant, and a list of which reads count cost code and held nothing. The check stays partial, as the finding decided: a copy built from separate reads passes. A first mode is `packet.start_mode`, so the packet hash covers it, and each rate a forcing varies records its class for ticket 10 (finding 17), which nothing enforces yet.
- **Late admission.** Each arrival is read off a run that does not hold the input. A known run's fence comes from what only it showed, so its heads hide the arrival a landing puts at risk: a planted cut-first bug showed in 13 of 120 rounds that way, against 39.
- **Rejected:** a core-located event, a claim on a proposal, an event field on a refusal, a landing tolerance of its own, `DiscreteState`, a seeded admission, `NegativeHazard`, `ConflictingHazards`, firing rounds, a second segment end at a reset, and a gate on an instance that edits a law's `ModeSet`.

**Evidence**, all synthetic, on this PR's final code unless a line says otherwise.

- **Mutation sweep.** A first sweep of 95 mutants left 18 survivors and 7 that crawled past their budget, and a timeout is no kill. Each survivor became a test or removed code: a firing's flag lost a second write, and finding 15's check lost a list of reads. A crawler gets its verdict from a limit per test. On the final code, 104 mutants chosen rule by rule: 103 killed. The sweep's last real survivor dropped the excursions a step ended on, and `a_firing_keeps_the_excursion_its_step_ended_on` now holds it. The one left sets a firing's flag after the loop as well, which changes nothing: `fire` runs only on a state where an armed guard crossed, and an assertion that every call fires held through the whole suite.
- **Two adversaries, one per vendor.** Each worked alone from the contract and the diff, on a head before the last fixes. Codex proved a shared integral losing an event and a rounded period. Opus proved the shared integral too, and six more: a bystander moving a landing, a stale seed-dependent test, events paired by position, a zero floor reaching a landing through `resume`, a validity range reading the rectified rate, and evidence that did not name its distance. Each is fixed and tested. Opus's last finding, the step-policy gate's reach, is the limit stated above. - **Differential fuzz.** Both adversaries' harnesses, in release with overflow checks and debug assertions, after porting the fixtures this PR now refuses. 1,383 random schedules and 12,000 dense stamps around a landing, through 7,943 firings and 17,972 refusals: no divergence from the known run. 24,485 landings over 256,220 tickets, at most 44 trials in a step, and the 12,329 on a watched stream past the first floor each held to a trial under its draw. 1,152 runs and 1.2 million revisions over forcing periods from a nanosecond to a century: no fault and no crawl. Resume, rewind and recover at every head of 150 rounds: no mismatch. Exact-rate firings held to threshold over rate in two review passes, 16,122 of them, with clocks near `u64::MAX` and floors from 1 ns.
- **Ordinary runs keep their bits.** A body with no stream, guard or forcing publishes what the base published: 3,724 lines of row bits and digests compare equal. The first run of this probe printed identical on zero lines, because a toolchain change had stopped both programs, so it now refuses empty output.
- **Cost.** A step with no chance went from 27.3 µs to about 28 µs, and the chance case costs about 39 µs, in release on one thread on the one fixture. A spline value costs about 15 ns, against about 1,400 ns from SHA-256 knots.

- **Ten local reviews, Codex Astra at max.** The first seven found nine issues, each fixed here: a firing into a state no law could read, the resume gate missing the head before a firing, a claim on finding 15's check, a panic in `CoupledProblem::new` on another body's values, a live pace that assumed a start at zero, a race test that stopped before its loser fired, a test named for a tolerance it never checked, a test that discarded its events, and a claim that the extra-evaluation gate sees dice keyed on an attempt. The last three passes found no defect in production code. The eighth found nothing, the ninth read this Answer and narrowed five claims, a test that never saw a refusal, a firing that can be dropped with its step, a gate said to compare events, a floor a narrow bracket goes under and a check that ran on half the landings, and the tenth read those fixes.

**Limits.** One small fixture, with hazards on two rates. Row scales stay uniform until ticket 10, so a hazard row's accuracy rests on step length. No `memory_rate` kernel can read an amount or a drive yet, so no input can move a crossing and the causal fuzz has not pressed that coupling. An added stream moves no draw, but when two guards cross in one span the landing reads one of them, so it can move the other's instant inside the floor, and a core may step differently in a bigger body. The step-policy gate cannot see a core that moves events by less than its distance.

**Hard-part check.** None reached. This ticket stayed contract machinery with synthetic values: no cross-site coupling, no validation against Pulse or published physiology, no stiff numerics and no disease.

## Comments

From 05: `StreamPositions` is in the checkpoint and in each image's digest, so a position is under the seal and `resume` already restores it, and ticket 04's note that `streams` proves only that the field is read stands until a draw moves one.
