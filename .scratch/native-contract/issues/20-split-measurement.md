# 20: A split is measured from accepted history

Spec: [First build slice](../../../docs/architecture/solver-contract.md#first-build-slice-spec)

**What to build:** The crates build split measurement as the contract lays it out: `PatientRecord::split_trace` draws a trace from accepted history, and `SplitMeasurement::qualify` is the only producer of a `SplitQualification`. It scores the four-family metric (state, exchange integral, observable, event time) against the reference integrator. §7's split gate then reads it, and runs under measurement are never scored.

Blocked by: None (can start immediately)

Status: resolved

- [x] A split qualification comes only from a measurement over traces from accepted history, scored against the reference integrator, and the sketch's two split probes hold in the crates

## Answer

A split solve is now trusted only on a measurement. `ng-contract` holds split measurement, `ng-record` reads accepted heads into it, and `ng-validate` runs §7's split gate against the reference integrator. All values are synthetic.

- **Traces from accepted history.** The history store keeps each step's ledger and no row's past value (ticket 11), so a trace is drawn while the run goes. The record holds its image as an `AcceptedHead`, which only `install` moves, and only with a `NextHead` that `AcceptedHead::attempt` settled: the contract builds the problem from the head's own parts, verifies the proposal, refuses a row outside its admissible set, and asks the record's ledger check. The step's `StepExtents` name the run and the heads it went from and to. `PatientRecord::split_trace` opens a `TraceDraw` on an admission head of its identity's packet, then reads each head with the receipt of the step that made it, and the draw keeps it only when those extents name the draw's run, the head read last and this head. A restored head, a head after one, and a head an input reached between its attempt and its install leave the draw's chain. Only `TraceDraw::finish` makes a `SplitTrace`. The families are every amount and memory row, every column's net extent since admission, every lens channel, and each firing after the grid's first instant.
- **The only producer.** `SplitMeasurement::qualify` normalizes each error by its family's scales at the reference's value. It adds the worst family to the reference's own error, and it refuses a total over one (`OverBudget`) or a reference error over its share (`ReferenceTooCoarse`). `SplitMeasurement::new` refuses traces of another patient or seed, grid, lens, applied inputs or event set, a run compared with itself, and a reference error measured on another reference. `ReferenceError::self_convergence(coarse, reference)` measures the reference's own error as its distance from a run with steps at least twice as long, and refuses a reference whose longest step is over half the coarser run's, or two runs that differ nowhere (`NotRefined`). At order one or more that distance is at least the finer run's error, so the split is measured against the finer run. A trace binds the patient by its bound values, because the packet hash also covers each core's method history at admission. It binds the inputs by the applied chain, which seals each delivery's id, time, amount, end, rate and route.
- **The split gate.** `split_gate` draws the reference integrator at its interval and at half, measures the split against the half, and takes the half's own error from its distance to the reference. It returns the qualification and nothing else, so no run it measured reaches a score. The tests are in `crates/ng-validate/tests/split.rs` and `crates/ng-validate/src/split.rs`. Measured with a throwaway probe on the stepped inflow case and a 7 s grid: a coupled core at 16 s errs by 2.78 in each grid family against the 4 s half, whose own error is 0.93; the ratio is 3.01, and the test asserts 2.9 to 3.1 per family. At scales of 10 the core qualifies with a total of 0.37. At 256 s it errs by 20.7 and is refused (total 2.16). On the ectopy case a 0.2 s core places firings up to 7.3 ms from the 0.05 s half of a 0.1 s reference, whose own error is 2.5 ms. On the closed case at scales of 1.2, the 16 s core's closed-form error is 1.24 of the budget, and the gate refuses it with a total of 1.24, its reference error 0.31 against the half's closed-form 0.31.
- **Probes.** Bytes as a qualification (E0308), a qualification written by hand (E0451), step extents written by hand (E0451), a head's parts written by hand (E0616) and a settled step written by hand (E0451) are in `crates/ng-contract/src/lib.rs`. A trace from invented samples (E0599) is in `crates/ng-record/src/lib.rs`. `gate.py codes` passes on all of them.
- **Review.** A local Codex pass and GitHub Codex found four holes at fe107e7, each with a repro: a state forged through public constructors, a refinement that moved nothing, inputs bound by id and not payload, and a firing at the opening instant (`~/lanes/logs/ng-nc-11-24/20/findings-before-fix.log`). The coordinator's local Codex pass at d8cee41 found two more, each with a counterexample: the reference error estimated the finer run's error while the split was compared with the coarser run, and extents that echo a caller's base let a caller feed a draw heads no step reached. Each now has a test that fails at d8cee41 (`~/lanes/logs/ng-nc-11-24/20/r2/`).
- **Mutation sweeps.** 25 rows at 62f039c (`~/lanes/logs/ng-nc-11-24/20/mutants-20b.toml`); 5 rows on the accounting and 18 on the accepted head in round two, all caught (`~/lanes/logs/ng-nc-11-24/20/r2/mutants-fix1.log`, `mutants-fix2.log`).
- **Not built.** `EvaluationPlan` holds `Coupled` and `QualifiedSplit`. The sketch's `UnderMeasurement` waits for the block seam, where a run's declared resolution can say it is under measurement.
- **Limits.** No `ng-contract` type can be one only `ng-record` makes, since a public item of one crate is public to every crate. So a course driven by hand through `AcceptedHead` draws a trace without a record. Every step of it is one the contract settled from an admission, with its own inputs, and it differs from a record's course in three ways only: it picks its own first spans, as a core that lies about its resolution does through a record; it can skip the record's `LedgerOverflow` refusal, which changes a course only when a running gross extent passes the f64 range; and a draw cannot follow a run across `resume`.
