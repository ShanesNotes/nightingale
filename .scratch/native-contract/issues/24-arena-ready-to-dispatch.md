## Answer

A seat scores its core with one call, `Arena::new(protocol)?.score(cores, second_policy, clock, store)` in `crates/ng-validate/src/arena.rs`, and gets back one `ArenaScore` (`src/score.rs`). The seat contract that names them is `~/lanes/briefs/ng-arena-seat-contract.md`, outside the repo, because `docs/governance.md` section 2 keeps briefs out. In the repo, usage (c) of `docs/architecture/solver-contract.md`, its section 7 evidence-binding bullet and the sketch's `ng_validate.rs` document the call, and `GLOSSARY.md` gains **Arena protocol** and a wider **Score**.

- **An arena seat contract names the validation crate's entry point and report schema, and both exist on main.** `one_arena_scores_the_reference_and_ng_solver_with_one_call_each` (`crates/ng-validate/tests/arena.rs`) builds one arena over a 2 s protocol from 06:55 and scores `ReferenceIntegrator` and `ng_solver::Core` with one call each. From each score it reads the timed run's throughput and numerical health, a certificate of the seal that run ended on over the protocol's windows, accuracy evidence of the run's resolution with six cases and one window, all seven replay gates on the run's identity with the stir fired once before the fence, and day checks whose fed run ended on the run's seal, rows 1 to 17 all not available yet. Both cores pass every part (measured, Omarchy, test profile). `past_the_sit_up_the_day_checks_end_on_the_timed_runs_seal` scores `ng_solver::Core` over 311 s, past the 07:00 sit-up: the day checks' fed run, which enqueues the plan's inputs, ends on the seal of the timed run, which knew them at admission.
- **The shape.** `ArenaProtocol` holds the certificate's sliding windows, whose coverage is the span from 06:55, the repeats, and the error scales and minimum interval every scored core declares. `ArenaProtocol::full()` is section 7's: 24 h windows over 48 h, two repeats, scales (0.1, 1e-3) and 0.1 ms, the solver arena's model defaults. `Arena::new` builds once what every core receives: the slice, its certificate policy (`arena_certificate`, ticket 14's synthetic limits), `AccuracyPolicy::arena()` with its window, and the day plan for every day the span reaches. `score` takes two closures that return one concrete core type, the core and the same core under a second step policy, so the step-policy gate cannot be handed another core (compile-fail `E0308` in `src/lib.rs`). A core that declares other scales or another interval is refused whole as `ArenaFailure::OffProtocol`, because the day checks read their tolerance from the scales. Every part runs on a fresh core: accuracy, the replay gates on a fresh `SliceCase`, the timed run with the day plan's inputs in its port, its certificate, then the day checks.
- **The report keeps the parts apart.** `ArenaScore` holds `evidence()` (identity, seal, resolution, throughput, health), `certificate()`, `accuracy()`, `replay()` and `day()`, each a `Result<_, &ArenaFailure>`, plus `protocol()` and `second_policy()`. A failed part keeps its failure (`ArenaFailure` gains `Certificate`, `Accuracy`, `Replay`, `Day` and `OffProtocol`, and derives `Debug`) and every other part stands; there is no overall pass bit. The day checks run whether or not the timed run succeeds, because they use a fresh core, keep no history, and read neither the clock nor the store; `bound` holds a part against the timed run only when there is one, so with none every part stands as its gate returned it and `evidence()` says why (`a_clock_with_no_reading_leaves_the_day_checks_and_accuracy_standing`). Each part is held against the timed run: the certificate by seal, accuracy by resolution and the arena's accuracy policy digest, replay by run identity, the day checks by the fed run's seal, which chains from the run identity (`crates/ng-record/src/history.rs` links the origin seal from it). The free `score` and `AccuracyEvidence::of_the_arena` are gone; their binding tests moved to unit tests of `bound` in `src/score.rs`, cheaper because they pass the manufactured policy's digest and build no window. Only `Arena::score` makes an `ArenaScore` (compile-fail `E0451`).
- **Changes under the gates.** `day_checks` keeps no history (a private store that keeps nothing and fails a walk closed), because its runs read only each step's head; it drops its store parameter. `MemoryStore` holds its links in a `BTreeMap`: its sorted `Vec` moved half the store on every insert, so the manufactured accuracy cases at `ng_solver::Core`'s 10 ms took 25.8 s at a 100 ms cap against 15.8 s with the map, and 162.8 s at 10 ms with the map (measured, Omarchy, release; by arithmetic about 1,160 s with the `Vec`). `DayPlan::events` makes the timed run's port and the day checks' enqueue from one list. The live pace counts a host clock from its first reading, since it adds readings to its run's start. `FaultReport` gains `Debug`, so the `told` helpers in the tests and the bench go. `tools/bench` gains `score <ms> <second ms> <core> <window s> <span s> <repeats>` and `score <ms> <second ms> <core> full`.
- **Planted faults.** At 60c89af, 7 of 9 rows were caught (`~/lanes/logs/ng-nc-11-24/24/mutants-24.log`). Two survived. Dropping the day checks' identity check survived because the seal already holds it, so that check is gone. A timed run whose port knew no input survived because no 2 s run applies one, so the 311 s test exists and the row is in `tools/gate/mutants.toml`. At 6056bfa all 10 rows of `mutants-24b.toml` were caught, the sit-up row, both protocol refusal rows and the live pace's clock row among them (`mutants-24b.log`). In this PR's second round, the row `day-waits-on-the-timed-run` puts back the old suppression of the day part on a failed timed run, and the clock test catches it (`r2-mutant.log`).
- **`ng_solver::Core` on the slice gates at its real cap** (measured, Omarchy, release): the manufactured cases pass at 10 ms in 162.8 s, and all seven slice replay gates pass at 10 ms with a 5 ms second policy in 39.3 s, the stir landing at 528.0595 ms, within 0.1 ms of a 10 ms reference at the window's scales and floor (`~/lanes/logs/ng-nc-11-24/24/probe-replay-solver-ref10.log`). So the pick of the solver arena stands on every part a short protocol scores. Its rows 2, 4 and 7 still fail from 06:55 to 07:30 (ticket 21, tower). Its full rescore waits for the two blockers below.
- **What a full run costs**, by arithmetic for `ng_solver::Core` at 10 ms on the tower from ticket 21's measured 06:55 to 07:30 run (2,100 simulated s, 308 s, 8.3 GB): each 48 h repeat takes 7.04 h and writes 683 GB of link log; the day checks run 179.5 simulated hours (the fed 48 h and six counterfactuals of 16,500 to 142,500 s, 131.5 h in all), 26.3 h, and now keep no history (2,554 GB before). Accuracy is about 4 min and the replay gates about 40 s. So `full()` with two repeats is about 40.5 h of wall time plus the certificate's unmeasured walk, and 1,366 GB on today's bench, whose `LinkLog` writes each repeat again (683 GB with a store that keeps a seal once). At section 7's 100 times real time it is about 3 h.
- **Two blockers for the full run, neither in this ticket.** The tower had 322 GB free (measured, `df`, 2026-11-07). And the certificate fails every core on energy drift past a few seconds: ticket 14's synthetic limit is 1e4 in each unit, and energy drifted 124,246 over the 155.5 s window from 06:55 (measured, the 311 s test, `~/lanes/logs/ng-nc-11-24/24/arena-test-3.log`), about 800 a second, so about 6.9e7 over 24 h by arithmetic. A synthetic energy drift limit for 24 h windows, or a slice that regulates heat, is the dispatcher's model default to set; the arena reports the failure as the certificate's part and every other part stands.
- **nightingale#38 and nightingale#39 do not block dispatch.** Either may move the slice's bits or model hash. Every seat is scored on one pinned commit; if either lands mid-arena, every seat rescores on the new head, since a part of another model hash is another run. The seat contract says so.
- **Measured cost of the proof** (Omarchy, test profile, under `heavy.sh`): `tests/arena.rs` ran 340 s with its two tests side by side, and the 311 s test 189 s alone. The rest of `cargo test -p ng-validate -p ng-record` passed beside it (`~/lanes/logs/ng-nc-11-24/24/tests-full-1.log`).
- **A store that refuses every write does not fail the timed run** (measured, in this PR's second round): the record holds a refused link in memory and offers it again on the next step, so `run` returns evidence and only the certificate's walk finds the link missing. So the clock, not the store, is the instrumentation failure the day test uses.
- Not in this ticket: a crate table row for each of foundation 01's `ng-solver-a` and `ng-solver-b`; `split_gate`, which the score does not run and which a split core needs; a link log that keeps each seal once; and a session path that takes no store for runs that keep none.

From 22: `score(certificate, accuracy, evidence, replay)` returns an `ArenaScore`, whose `certificate()`, `accuracy()`, `evidence()` and `replay()` each state the policy values they were judged by. A part of another run is `ArenaFailure::MissingEvidence { part }`. Certify `arena.session().conservation()` before `into_evidence()`, because the certificate must certify the exact `HistorySeal` the run ended on. Accuracy evidence must come from the run's whole `DeclaredResolution` under `AccuracyPolicy::arena()`, every manufactured case and `SliceWindow::first()` at the default bound and grid. `score` reads that from the cases the evidence ran without building the window again, since `first()` is the only window: a second window constructor needs its own identity in that check. The accuracy gate runs the manufactured cases at the arena core's own step. Those cases cover about 34,000 simulated seconds, which is about 6.8 million steps at a 5 ms step, each case in its own `MemoryStore` (arithmetic). The run identity reads no boundary port, so replay evidence on another timeline of the same identity passes. `ArenaFailure` has no `Certificate`, `Accuracy` or `Replay` variant yet, so an entry point that composes the gates needs them.

From ticket 21: `day_checks` returns a `DayReport` for the report to hold whole, beside the score. `tools/bench`'s `day <interval ms> <core> <simulated s>` prints it.
