## 2. Bound four-seam contract and two provenance rules

Every learned model meets the engine at exactly one of the four active seams below. The fifth seam, inside the engine, remains closed: laws are closed expression kernels (`docs/srs.md` rule 8), and fitted weights lack `Source record` or `Inference record` backing under SRS rule 12 until a decision record and contract version exist.

| Seam (builds) | Input and returned types | Engine or verifier gate | Allowed claims | Forbidden transitions |

**Bound provenance rules:**

1. **Checked proposals earn no provenance and need none.** Any input entering Seam 1 receives only the engine's own `InitializationProvenance` (`ValueProvenance::{Fixture, Derived, Sampled, Authored, Calibrated, Solved}`, `provenance.rs:155-177`) and `PacketHash::reading` (`packet.rs:57`, sealing solved `start`, `modes`, `fitted`, `witness`, and `MethodHistory`). `ParameterPacket<Reviewed>` remains restricted to `Citation` and `InferenceRecord` per SRS rule 16 (`packet.rs:37-45`). When multiple admitted rests exist (`native-contract 86`), replay reproduces the reached start via `nc86`'s chosen mechanism while `admit` remains sole arbiter.
2. **Unchecked predictions carry a label and name what taught them.** Every non-proposal model (`Seam 2`, `Seam 3`, `Seam 4`) emits `claim_label` in `{validated, approximate, untested}` (`ticket 01` section 6) inside its `artifact_manifest.json` (`L10`) naming `engine_commit`, `model_hash`, `dataset_manifest_digest`, `frozen_digest`, and `outside_checks`, and never supplies a `Source record` or `Target` (SRS rule 16, record 0003).

## 3. Rule-by-rule disposition (`L1` to `L14`)

Each rule from [ticket 16](issues/16-architecture-foundations.md) section 3 was challenged for scope contradictions across `C2`, `5.2`, `5.3`, `5.5`, `5.6`, missing negative refusals, and runtime loopholes.

### L1. Engine-only physiological authority
- **Disposition: Keep.** Core boundary already holds in `crates/ng-contract/` and `crates/ng-record/`, provided tests also cover `ParameterPacket<Reviewed>` anchor exclusion and `Checkpoint::from_bytes` tamper rejection.
- **Bound rule:** No learned prediction enters `InitialRevision` or `PatientRecord` except as a Seam 1 proposal accepted whole by `InitializationSystem::admit`, `Session::enqueue`, or `PatientRecord::attempt` / `publish`.
- **Positive test:** Pass a perturbed `AdmissionWorkspace` inside Newton tolerance into `InitializationSystem::admit` -> returns `Ok(InitialRevision)` with `worst()` within `ErrorScales`.
- **Must-fail negative test:** Perturb one `AdmissionWorkspace` unknown past `ErrorScales` and call `admit` -> returns `Err(InitializationFailure::Inconsistent { .. })`; flip 1 byte in `Checkpoint` and call `Session::resume` -> returns `Err(CheckpointError::Corrupt)`; doctests attempting direct `PatientRecord` or `InitialRevision` construction fail to compile (`E0451`/`E0599`).
- **Enforcement layer:** Rust type boundary (`10-rust` doctests and unit tests in `crates/ng-contract/` and `crates/ng-record/`).

### L2. Conservation by derived two-ended transfers
- **Disposition: Change.** Draft `L2` conflicted with `C2` (`ticket 08`, readings-only recurrent hidden vector with no conserved amounts) and with rate-driven non-material `memories` (`tickets 07, 08`). Further, static `P S = B A` alone does not catch unpaired runtime updates in Python rollouts.
- **Bound rule:** Every conserving model (`conserving == true`: `C1`, `C4a`, `R`, and `5.4` named models) moves amounts exclusively through transfers or reactions compiled from the engine's columns, satisfying integer `P S = B A` at reduction compile time (including integer stoichiometry for reactions) and `|totals(t) - totals(0) - B @ cumulative_extents(t)| <= 64 * 2^-52 * scale` with donor-gated nonnegative outflows at runtime; `memories` evolve only by declared rates, and non-conserving baselines (`C2`) declare `conserving: false`.
- **Positive test:** Compile valid named and `each-row` reductions verifying `P S == B A` in exact integers; roll forward `C1` and `C4a` under random weights for 1,000 steps checking closure within `64 * eps * scale` and nonnegativity.
- **Must-fail negative test:** Drop one active pool from a reduction without marking it `held`, or misclassify a multi-pool reaction column -> `Reduction::compile` refuses (`P S != B A` or unclassified pool); inject an unpaired `+1e-6` delta or nonzero outflow from a zero pool in a synthetic `models.py` forward pass -> `gp.py selftest` fails.
- **Enforcement layer:** `gp-driver` `Reduction::compile` (`10-rust`) + `gp.py selftest`.

### L3. Readings never feed forward physiological dynamics
- **Disposition: Change.** Blanket wording appeared to ban `5.5` (reads state), `5.6` (reads observations to infer packets), `Rule.react` (reads noisy beats to emit `BoundaryEvent`), and `C2`'s `ReadingsStart`.
- **Bound rule:** Forward physiological stepping (`LearnedRun.advance` and engine `Session::step`) accepts no `Observation`, `ObservationLens`, `ObservationSeed`, or query cadence; `C1`/`C4a`/`R` start only from `NamedStart`, `C2` accepts `ReadingsStart` only at `start()` and feeds only its own noiseless predictions during `advance()`, and `Rule.react` enters only via `enqueue`.
- **Positive test:** Run `C4a` and `C2` over identical events and seeds while querying `beats()` every 1 s vs once at the end and under two `ObservationSeed` values -> final serialized state bytes and `beats()` match bit for bit.
- **Must-fail negative test:** Pass `ReadingsStart` to a named `Model.start` or pass a lens/observation argument to `LearnedRun.advance` -> raises `TypeError`; inject a synthetic model whose `advance` mutates state on `beats()` call count -> fails cadence invariance in `gp.py selftest`.
- **Enforcement layer:** Python runtime type boundary (`Model.start`, `LearnedRun.advance`) + `gp.py selftest`.

### L4. Seed domain isolation and zero unkeyed step randomness
- **Disposition: Change.** Draft phrasing ("draws nothing of its own") conflicted with keyed stream draws in `5.4`, `ObservationSeed` draws in `5.5`, and posterior proposal draws in `5.6`.
- **Bound rule:** Runtime randomness uses only three separated domains: `PacketSeed` (trait draws and Seam 3 packet proposals), `Seed` (rate forcing and hazard integrals keyed by `(seed, stream_key, event_ordinal)` acting only on rates or event firing, never amounts), and `ObservationSeed` (`5.5` measurement error and artifacts). `5.4` rollouts never use global RNG, dropout, or per-step sampled latents; adding a stream or channel shifts no other draw.
- **Positive test:** Run `LearnedRun` and `Observer` with fixed `(PacketSeed, Seed, ObservationSeed)`, append an unused stream or channel, and re-run -> original stream draws and state bytes are bit-identical; changing `ObservationSeed` leaves `LearnedRun` state bits unchanged.
- **Must-fail negative test:** Pass `Seed` to `Observer::new` -> fails Rust compile (`E0308`, `crates/ng-observe/src/lib.rs:6-10`); inject `random.random()` or an unkeyed per-step latent sample into a synthetic `5.4` forward pass -> fails seed-repeatability in `gp.py selftest`.
- **Enforcement layer:** Rust type boundary (`DomainSeed<D>`, `10-rust`) + `gp.py selftest` (determinism, isolation, and AST/RNG guard).

### L5. Bitwise replay across pace, call chunking, and resume
- **Disposition: Change.** `ticket 08` splits integration steps at events and beat edges, whereas caller `advance(until_ns)` calls can land mid-step (`SA`'s caller-clipping bug, `docs/architecture/solver-contract.md:445`). Piecewise event tests also differ from chunking when an added event falls inside an integration step.
- **Bound rule:** `LearnedRun.advance(until_ns)` never clips an integration step at caller `until_ns` (stepping only to the model's fixed/breakpoint grid up to `until_ns` and holding any partial grid remainder), so arbitrary call chunking, pace, and `checkpoint()` + `resume()` yield identical bits within the pinned CPU single-thread float64 runtime (`FROZEN`). Adding a redundant physical event mid-step matches within the scheme's integration tolerance (and bitwise on grid boundaries).
- **Positive test:** Compare `advance(T)`, irregular mid-step splits `advance(t_k)` (e.g. `137_000_000 ns`), and `checkpoint()` + `resume()` mid-run -> serialized state bytes, `totals`, and `beats()` match bit for bit.
- **Must-fail negative test:** Build a synthetic runner that clips RK4 steps at caller `until_ns` or omits recurrent hidden buffers from `LearnedCheckpoint` -> fails arbitrary-split and resume bit-equality tests in `gp.py selftest`.
- **Enforcement layer:** `gp.py selftest` + pinned runtime digest in `FROZEN`.

### L6. Learned dynamics object is a rate per simulated second
- **Disposition: Change.** Draft `L6` gave no boundary for `C2` (`ticket 08` puts `C2` outside `L6`) or non-dynamical models (`5.2`, `5.3`, `5.5`, `5.6`), and omitted the smoothness constraint needed for RK4 order convergence (`C^0` activations drop order).
- **Bound rule:** Every continuous-time dynamics model (`continuous_rate == true`: `C1`, `C4a`, `R`, and hazard-rate modules) learns a `dt`-free rate `(state, traits, drive) -> rate_per_s` with `C^2`-smooth activations (`tanh`/`softplus`) achieving declared integrator convergence order on smooth intervals; `C2`, `5.2`, `5.3`, `5.5`, and `5.6` declare `continuous_rate: false` and stay outside `L6`.
- **Positive test:** Integrate a smooth synthetic `C1` or `C4a` model with zero events at step `h`, `h/2`, `h/4` against `h/16` reference -> observed RK4 convergence order `>= 3.5`.
- **Must-fail negative test:** Construct a synthetic model whose rate module embeds a hardcoded step factor or reads `dt` directly -> step-halving order collapses (`< 1.0`) and fails `gp.py selftest`.
- **Enforcement layer:** `gp.py selftest` (`step_halving_order` + rate-signature check).

### L7. Independent outside check for physiological claims
- **Disposition: Change.** Draft `L7` did not enforce independence from sources already used to author engine laws (`ticket 14` vs `research 13`) or restrict synthetic-packet checks to direction/ordering under SRS rule 16.
- **Bound rule:** Seam 1 (`5.2`, `5.3` Stage A ranking) and Teacher Data (`5.1`) make no physiological claim and require no outside check. Every model claiming physiological behavior (`5.3` Stage B fit, `5.4`, `5.5`, `5.6` clinical scenario claims) names >= 1 clinically reviewed literature source (`outside_checks`) disjoint from `engine_law_sources` and training data, evaluated with `claim_mode: "direction_only"` on `SyntheticFixture` runs and held-out calibration/metrics on `Reviewed` packets.
- **Positive test:** Check an `artifact_manifest.json` for `C4a` (`SyntheticFixture`) carrying `outside_checks` with distinct citation and `claim_mode: "direction_only"`.
- **Must-fail negative test:** Submit a `5.4` or `5.3` Stage B artifact manifest with empty `outside_checks`, with a citation present in `engine_law_sources`, or with `claim_mode: "clinical_magnitude"` on a `SyntheticFixture` teacher -> refused by manifest validator (`gp.py selftest`).
- **Enforcement layer:** Artifact manifest validator + `Study` gate check + `gp.py selftest`.

### L8. Pre-tuning study freeze and single-read held-out isolation
- **Disposition: Change.** Draft `L8` did not enforce partition isolation against `fit`/`call`, `train.py` tuning exclusion (`ticket 09`), or single-evaluation locking (`ticket 12`).
- **Bound rule:** Before any `fit` or `call`, `FROZEN` stores SHA-256 digests of every tracked file under `tools/generative-physiology/` except `FROZEN` and `train.py`. `fit`, `call`, and `evaluate` refuse any tree mismatching `FROZEN`, `gp.py selftest` runs `freeze --check` whenever `FROZEN` exists (plus a temp-tree fixture test before `FROZEN` is committed), `fit` and `call` refuse any manifest with `partition == "heldout"` or shared `PacketSeed`/start-history overlap with `heldout`, and `evaluate` writes a one-shot receipt refusing re-evaluation under the same `FROZEN` digest once `train.py` or weights change.
- **Positive test:** Verify `gp.py freeze --check` passes on an unaltered frozen fixture tree, `fit`/`call` accept `train`/`validation` manifests, and `evaluate` writes one valid receipt.
- **Must-fail negative test:** Alter 1 byte of a frozen file (`spec.py` or `features.py`) without updating `FROZEN` -> `freeze --check` fails naming that file (`10-rust`); pass a `heldout` manifest to `fit` or `call` -> refused (`PartitionError`); invoke `evaluate` a second time after editing `train.py` under the same `FROZEN` digest -> refused (`AlreadyEvaluatedForFrozenDigest`).
- **Enforcement layer:** `FROZEN` digest check in `gp.py` + `gp.py selftest` (under `10-rust`, `tools/gate/paths.toml:14-16`) + partition/receipt guard in `fit`/`call`/`evaluate`.

### L9. Complete accounting of faults and admission refusals
- **Disposition: Change.** `tools/generative-physiology/driver/src/teacher.rs:741-749` and `main.rs:213-215` show `gp-driver` exits `1` on `InitializationFailure` without writing an archived `.refused` directory, silently dropping admission refusals needed by `5.2`/`5.3` feasibility surfaces (`L9`).
- **Bound rule:** Every planned run in a dataset ends in one closed outcome: `complete`, `fault` (`EngineFault` or `MemoryCap`), or `refused` (`AdmissionError` or `InitializationFailure`). `gp-driver` persists `.fault/` and `.refused/` directories atomically; `dataset_manifest.json` lists every planned `spec_id` with exact counts (`total_planned == complete + fault + refused`). Exporters exclude non-complete trajectories from dynamics fits while retaining all failures in counts and feasibility surfaces.
- **Positive test:** Check a mixed synthetic corpus (`complete`, planted `MemoryCap` `.fault`, planted `Inconsistent` `.refused`) -> `manifest.py` verifies `total_planned == complete + fault + refused` and digest match.
- **Must-fail negative test:** Delete one `.fault` or `.refused` directory on disk, omit one `spec_id` from `entries`, or alter `counts` in `dataset_manifest.json` -> manifest validator and `gp.py export` refuse (`ManifestMismatch`).
- **Enforcement layer:** `gp-driver` archival (`10-rust`) + manifest validator + `gp.py selftest`.

### L10. Artifact provenance manifest and load-mismatch refusal
- **Disposition: Change.** Draft `L10` required `reduction_digest` for all models (contradicting `C2`, `5.2`, `5.3`, `5.5`, `5.6` which carry no reduction) and listed raw `packet_hashes`/`spec_ids` without chaining via `dataset_manifest_digest`.
- **Bound rule:** Every learned artifact carries an `artifact_manifest.json` binding `engine_commit`, `crates_tree_digest`, `model_hash`, `dataset_manifest_digest`, `packet_hashes_digest`, `reduction_digest` (SHA-256 required when `conserving == true`, `null` otherwise), `frozen_digest`, `train_script_sha256`, `training_seed`, `runtime_env_digest`, and `weights_sha256`. `load()` verifies `artifact_digest`, `weights_sha256`, `model_hash`, `reduction_digest` (when `conserving`), and `frozen_digest` (must be non-null and match active `FROZEN` whenever `FROZEN` exists, and must match `FROZEN` whenever set) before executing.
- **Positive test:** Load a synthetic `C4a` artifact with matching `model_hash`, `reduction_digest`, `frozen_digest`, and `weights_sha256`, and a `C2` / `5.2` artifact with `reduction_digest: null` -> both load cleanly.
- **Must-fail negative test:** Load any artifact against a different `model_hash`, wrong `reduction_digest`, mismatched `frozen_digest`, corrupted weight byte, or missing `dataset_manifest_digest` -> `models.load()` refuses (`ArtifactMismatch` / `CorruptArtifact`).
- **Enforcement layer:** Artifact manifest validator + `models.load()` guard + `gp.py selftest`.

### L11. Read-only support signal, published excursions, zero clamping
- **Disposition: Keep.** Clarified with non-perturbation: support evaluation must never feed back into state transitions or clamp amounts.
- **Bound rule:** Every `5.4` standing-in model computes a read-only support signal (`inside` vs `outside_support`, training-set distance and seed spread) per step/beat. Outside support, the model never clamps states, rates, or predictions; it publishes and logs every excursion (`excursion_count`) and fails with `ModelFault` if an amount would turn negative despite step halving (`ticket 08`). Reports stratify metrics over `inside_support`, `outside_support`, and `all`.
- **Positive test:** Run a `5.4` model on an in-support case and a planted out-of-support case (`10x` training distance) under two support cutoffs -> state bits remain identical across cutoffs, `excursion_count > 0` on the out-of-support case, and report contains non-empty `inside_support` and `outside_support` strata.
- **Must-fail negative test:** Inject state clamping (`x = max(x, 0.0)`) or suppress excursion logging on a planted out-of-support state, or emit a report lacking `outside_support` breakdown when `excursion_count > 0` -> fails `gp.py selftest`.
- **Enforcement layer:** `LearnedRun` / `Study` evaluator + `gp.py selftest`.

### L12. Exclusion of real-person data
- **Disposition: Change.** Draft test ("dataset's manifest lists teacher runs only") rejected valid `5.6` authored scenario evaluation charts (`ticket 16` line 253) while failing to block real-patient empirical covariate fits (`PhysicalAI`-style) inside `ParameterPacket` inputs.
- **Bound rule:** Every training, fitting, or library dataset (`5.1`–`5.5` and `5.6` training) requires `origin == "engine_teacher"` with verifiable `(spec_id, model_hash, packet_hash, run_identity)` and `packet_kind` in `{synthetic_fixture, reviewed_literature_packet}` (`population` entries cite literature, never empirical real-patient regressions). Evaluation-only `5.6` charts may use `origin == "authored_scenario_eval"` with non-clinical attestation and zero patient identifiers, and are refused by `fit`/`train`. Every artifact/report carries the non-clinical teaching notice (`docs/srs.md` section 1).
- **Positive test:** `train` manifest with `origin: "engine_teacher"` passes manifest checks; `5.6` eval manifest with `origin: "authored_scenario_eval"` passes `evaluate` while being refused by `fit`.
- **Must-fail negative test:** Present a dataset entry with `origin: "real_patient"` / `"clinical_record"`, an `engine_teacher` entry missing `spec_id` or `run_identity`, an `authored_scenario_eval` manifest passed to `fit`, or an unapproved raw `.csv`/`.npy` data file tracked in git under `tools/generative-physiology/` -> refused by manifest validator and `gp.py selftest`.
- **Enforcement layer:** Manifest validator + `fit` guard + `gp.py selftest` (with `10-rust`).

### L13. Exhaustive observer feature accounting
- **Disposition: Change.** Draft `L13` mixed `Chart` documentation (`SRS rule 1`, `rule 16`) with `Observer` (`ng-observe`) and lacked machine-checked `convention` invariance and typed-absence tests.
- **Bound rule:** Every `5.5` observer (instrument or qualitative; `Chart` documentation remains separate under SRS rule 1) supplies an exhaustive `feature_accounting` map classifying every emitted channel/feature as: `produced` (`state_rows` non-empty, recovered within error tolerance), `instrument` (`seed_domain == "observation"`, sourced accuracy/agreement study), or `convention` (`state_rows == []`, invariant to non-rhythm physiological state, refused by clinical scenarios requiring it as physiological signal). Absences emit `ObservedValue::{NotCollected, Pending, InvalidSignal}`, never `0.0`.
- **Positive test:** Valid observer manifest passes beat-count parity against ECG beat edges, pressure wave beat-mean fidelity, `Pending` -> `Present` delay transition, and invariant `convention` wave shape across two distinct blood pressures at fixed rhythm phase.
- **Must-fail negative test:** Leave a channel unclassified in `feature_accounting`, draw `instrument` noise from run `Seed` (`E0308`), emit `0.0` for `NotCollected` (`E0308`), or mutate a `convention` feature when pressure changes -> refused by Rust doctests (`crates/ng-observe/src/lib.rs:6-46`), observer validator, and `gp.py selftest`.
- **Enforcement layer:** Rust type boundary (`ng-observe`, `10-rust`) + observer manifest validator + `gp.py selftest`.

### L14. Cheapest baseline first under frozen promotion bar
- **Disposition: Change.** Draft test ("gate's table carries the baseline's row") checked table formatting without enforcing promotion refusal when a richer model ties or loses to the baseline (`ticket 11` `study.call`, `5.2` ladder).
- **Bound rule:** Every build defines and runs its cheapest baseline first in the frozen ladder (`5.2`: packet guess -> nearest admitted -> continuation -> linear map; `5.3`: Stage A / GP-ARD before neural emulator; `5.4`: `C1`/`C2` before `C4a` and conditional `R`; `5.6`: population draw matching before nearest/amortized). A richer rung is promoted only when the frozen selection rule (`study.call` `D > w and lo > 0`, or `5.2` pre-declared speedup factor with tolerance match) strictly passes on `validation` cases without reading `heldout`.
- **Positive test:** Synthetic `ValidationScores` where `C4a` satisfies `D > w and lo > 0` over `C1` and `C2` promote `C4a`; when `C4a` ties `C2`, `study.call` selects `add="R"`.
- **Must-fail negative test:** Feed synthetic scores where `C4a` ties or loses to `C1` (`D <= w`) and assert `study.call` keeps `C1` (refusing promotion of `C4a`); attempt to promote `R` when `C4a` already beat `C2` or omit baseline rows from the gate table -> fails `gp.py selftest`.
- **Enforcement layer:** `study.call` / ladder gate + `gp.py selftest`.

## 4. Two architectural shapes compared

### 4.1 `L9`/`L10` dataset and artifact manifest layout

- **Shape A (Canonical line-text `gp-manifest 1` / `gp-artifact 1`):** Flat sorted key-value line records extending `summary.txt` (`tools/generative-physiology/driver/src/archive.rs:359-410`) and `catalogue.txt` (`capture.py:98`), parsed via `_Lines` without JSON nesting. Pros: zero nested parser ambiguity and matches existing driver text formats. Cons: awkward for lists (`entries`, `outside_checks`, `feature_accounting`) and forces custom parser updates whenever a field is added.
- **Shape B (Canonical JSON `dataset_manifest.json` and `artifact_manifest.json`):** Sorted-key compact JSON (`json.dumps(..., sort_keys=True, separators=(",", ":"))`) with full-payload SHA-256 self-digest (omitting only the self-digest key), extending `ticket 05`'s `reduction-*.json` pattern (`Python 3.11` stdlib `json` only).

**Exact required fields (Shape B):**
- **`dataset_manifest.json`:** `schema_version` (`1`), `partition` (`train | validation | heldout | library | audit`), `origin_policy` (`engine_teacher | authored_scenario_eval`), `source_commit`, `crates_tree_digest`, `model_hash`, `frozen_digest` (`string | null`, required non-null for study partitions), `counts` (`{total_planned, complete, fault, refused}`), `packet_hashes_digest` (SHA-256 of sorted unique `packet_hash` hex strings), `entries` (sorted by `spec_id`, each `{spec_id, origin, packet_kind, packet_hash, resolution_digest, run_identity, outcome, detail, summary_sha256, parent_spec_id}` where `origin` is `engine_teacher | authored_scenario_eval`, `packet_hash` is pre-admission `ParameterPacket::hash()` present even when `outcome == "refused"`, and `run_identity` is `null` iff `outcome == "refused"`), and `manifest_digest`.
- **`artifact_manifest.json`:** `schema_version` (`1`), `artifact_kind` (`start_proposer | emulator_stage_a | emulator_stage_b | gp_model | observer | chart_inference`), `family` (`nearest | continuation | linear_map | gp_ard | neural_emulator | C1 | C2 | C4a | R | instrument | qualitative | npe | fmpe`), `claim_label` (`proposal_only | validated | approximate | untested`), `conserving` (`bool`), `continuous_rate` (`bool`), `engine_commit`, `crates_tree_digest`, `model_hash`, `dataset_manifest_digest`, `packet_hashes_digest`, `reduction_digest` (`string | null`, required if `conserving`), `frozen_digest` (`string | null`), `train_script_sha256`, `training_seed`, `runtime_env_digest`, `weights_sha256`, `outside_checks` (`[{citation, source_set_tag, claim_mode}]`), `feature_accounting` (`null` unless `observer`), and `artifact_digest`.
- **Digest chain and refusal conditions:** `manifest_digest` hashes the full sorted-key compact JSON with `manifest_digest` omitted (sealing `partition`, `origin_policy`, `model_hash`, `frozen_digest`, `counts`, `packet_hashes_digest`, and all `entries`), and each entry's `summary_sha256` binds `summary.txt` (or `refusal.txt`) on disk. `artifact_digest` hashes the full sorted-key compact JSON with `artifact_digest` omitted (sealing `weights_sha256`, `dataset_manifest_digest`, `packet_hashes_digest`, `model_hash`, `reduction_digest`, `frozen_digest`, `outside_checks`, `feature_accounting`, and `claim_label`). Validators refuse: missing/duplicate `spec_id`; `total_planned != complete + fault + refused`; any `.fault`/`.refused` directory omitted from `entries`; `summary_sha256`, `manifest_digest`, `artifact_digest`, or `weights_sha256` mismatch; `origin != "engine_teacher"` when `origin_policy == "engine_teacher"` or on training/library manifests; `partition == "heldout"` passed to `fit`/`call`; `model_hash`/`reduction_digest` mismatch on `load()`; `frozen_digest` null or mismatching active `FROZEN` (when `FROZEN` exists, or whenever `frozen_digest` is set); empty `outside_checks` when `claim_label != "proposal_only"`.
- **Model default:** **Shape B** (`dataset_manifest.json` / `artifact_manifest.json`). Tradeoff: relies on canonical `sort_keys=True` JSON serialization in Python in exchange for structured nested checks (`counts`, `outside_checks`, `feature_accounting`) consistent with `ticket 05`'s `reduction-*.json`.
- **One-line alternative:** Shape A (`gp-manifest 1` / `gp-artifact 1` line-text files) if `gp-driver` must parse or emit manifests in Rust without adding a JSON parser crate.

### 4.2 Rule enforcement layering across `tools/generative-physiology/`

- **Shape A (Centralized CLI gate `rules_gate.py`):** One standalone Python gate inspects directories, `FROZEN`, and manifests around CLI entrypoints in `gp.py`, keeping `models.py` and `study` modules unaware of rules `L1`–`L14`. Pros: one inspection file. Cons: duplicates parsing/state knowledge and is bypassed whenever Python code imports `models.load()` or `Study` directly.
- **Shape B (Boundary-embedded four-layer enforcement):** Each rule lives at the constructor/loader/API boundary that owns its state:
  1. **Rust types and `gp-driver` (`10-rust`):** `L1` (`PatientRecord`, `InitialRevision`, `admit`), `L4`/`L13` (`DomainSeed<D>`, `ObservedValue`), `L2` (`Reduction::compile` `P S = B A`), `L9` (atomic `.fault` / `.refused` directories).
  2. **Manifest and study loaders (`manifest.py`, `freeze.py`, `models.load()`, `Study.frozen()`):** `L7`, `L8` (`FROZEN`, `heldout` partition lock, single `eval_receipt`), `L9`, `L10`, `L12`, `L13` (`feature_accounting`), `L14` (`study.call`).
  3. **Model runtime APIs (`models.py`, `LearnedRun`):** `L2` (`totals += B @ extents`), `L3` (`advance` takes no readings/lens), `L4` (keyed RNG only), `L5` (grid-aligned `advance`, no caller clipping), `L6` (`dt`-free smooth rates), `L11` (read-only support excursion, `ModelFault` on negative step, zero clamping).
  4. **Fast regression gate (`gp.py selftest` under `tools/verify.d/10-rust.sh`):** runs positive + planted must-fail negative tests for `L2`–`L14` and `freeze --check` whenever `FROZEN` is present.
- **Model default:** **Shape B** (boundary-embedded four-layer enforcement). Tradeoff: rules distribute across Rust and Python modules (requiring this specification's table), in exchange for non-bypassable parse-once boundaries and immediate fast-gate feedback via `tools/gate/paths.toml:14-16`.
- **One-line alternative:** Shape A (centralized `rules_gate.py` CLI wrapper), used only if unreviewed external scripts invoke `gp-driver` directly without importing `Study` or `models`.
