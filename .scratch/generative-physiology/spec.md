Section 1.1 says which checks named here run now and which wait for code that tickets 05 to 12 plan. A review read each claim here against the engine at the commit below, and ticket 16's Comments say what it changed.

## 2. Draft four-seam contract and two provenance rules

Every learned model meets the engine at exactly one of the four active seams below. The fifth seam, inside the engine, remains closed: laws are closed expression kernels (`docs/srs.md` rule 8), and fitted weights lack `Source record` or `Inference record` backing under SRS rule 12 until a decision record and contract version exist.

| Seam (builds) | Input and returned types | Engine or verifier gate | Allowed claims | Forbidden transitions |
|---|---|---|---|---|
| **1. Proposal** (`5.2` start guesses, `5.3` candidates for a fit, `5.6` packet proposals) | Out to engine: `ParameterPacket<K>` (`crates/ng-contract/src/packet.rs:190`), `AdmissionWorkspace` (`crates/ng-contract/src/admission.rs:413`, via `unknowns_mut` `:424` and `shift_crossing` `:474`). In from engine: `InitialRevision` (`admission.rs:1832`). | `CompiledBody::bind` (`packet.rs:823`), `InitializationSystem::admit` (`admission.rs:1663`, rechecking workspace alone via `check` and `recheck`). | None of its own. Validity rests solely on the engine check and `RunIdentity` (`crates/ng-contract/src/scheme.rs:364`). | Direct construction or mutation of `PatientRecord` (`crates/ng-record/src/record.rs:26`, no public constructor or setter) or `InitialRevision`; bypassing `InitializationProvenance` (`crates/ng-contract/src/provenance.rs:225`); injecting learned predictions into `ParameterPacket<Reviewed>` anchors (`packet.rs:37-45`, SRS rule 16); resuming a checkpoint the engine did not write. `restore` (`crates/ng-record/src/checkpoint.rs:280`) detects corruption and does not judge a host-written file, so `L1` holds this on the host's side. |

Standing in** (`5.4` generative physiology models: `C1`, `C2`, `C4a`, `R`) | In: teacher runs (`Summary`, `Catalogue`, `Edges`, `RunSpec`), compiled `Reduction` (`tickets 05, 08`), `DatasetManifest`. **Outside the seams.** Two things meet the engine at none of them.

- A model that chooses inputs. Ticket 16 says it "is none of the five". Its action is an authored event that enters through the boundary port with `Session::enqueue` (`crates/ng-record/src/session.rs:154`), which checks the fence and not the choice. Neither the run identity nor the packet hash covers it: "Events stay out of it" (`crates/ng-contract/src/packet.rs:56`). Measured on the two-reservoir fixture: an enqueued delivery changed the state while both stayed equal. A replay holds an action only through the event log (SRS rules 4 and 13).
- The `5.3` ranking. It reads teacher runs offline and returns an order of the engine's constants. It sets no value and proposes nothing, so it claims something about the engine and nothing about physiology. It carries rule 2's label and names what taught it.

**Draft provenance rules:**

1. **Checked proposals earn no provenance and need none.** Any input entering Seam 1 receives only the engine's own `InitializationProvenance` (`ValueProvenance::{Fixture, Derived, Sampled, Authored, Calibrated, Solved}`, `crates/ng-contract/src/provenance.rs:155-177`) and `PacketHash::reading` (`crates/ng-contract/src/packet.rs:57`, sealing solved `start`, `modes`, `fitted`, `witness`, and `MethodHistory`). A `Reviewed` packet's trace is a `Citation` (`packet.rs:37-45`), and no crate builds one yet. No type for an inference record exists in the crates: record 0003's inference records live in `data/`. When multiple admitted rests exist (`native-contract 86`), replay reproduces the reached start via `nc86`'s chosen mechanism while `admit` remains sole arbiter.
2. **Unchecked predictions carry a label and name what taught them.** Every non-proposal model (`Seam 2`, `Seam 3`, `Seam 4`) emits `claim_label` in `{validated, approximate, untested}` at a stated `claim_level` from 1 to 5 (`ticket 01` section 6: fit, free run, intervention response, closed loop, independent evidence) inside its `artifact_manifest.json` (`L10`) naming `engine_commit`, `model_hash`, `dataset_manifest_digest`, `frozen_digest`, and `outside_checks`, and never supplies a `Source record` or `Target` (SRS rule 16, record 0003).

## 3. Rule-by-rule disposition (`L1` to `L14`)

Each rule from [ticket 16](issues/16-architecture-foundations.md) section 3 was challenged for scope contradictions across `C2`, `5.2`, `5.3`, `5.5`, `5.6`, missing negative refusals, and runtime loopholes.

### L1. Engine-only physiological authority
- **Disposition: Change.** The engine's types hold this rule at admission and not at a checkpoint. `restore` checks a raw SHA-256, the run identity, the latch and the seal chain, and each is a digest with no key. The contract accepts that: "it detects corruption, not a forger" (`docs/architecture/solver-contract.md:671`, and line 334). Measured on the two-reservoir fixture: a host wrote checkpoint bytes holding a start that `admit` refuses as `Inconsistent`, recomputed the digests, and `Session::resume` (`crates/ng-record/src/session.rs:132`) took them under the admitted run's identity and stepped. So the rule needs a half on the host's side, and ticket 16's draft of `L1` missed it too.
- **Draft rule:** No learned prediction enters `InitialRevision` or `PatientRecord` except as a Seam 1 proposal that `InitializationSystem::admit` accepts whole. The driver resumes only a checkpoint that the engine wrote in a run its archive lists, and it writes no checkpoint bytes of its own.
- **Positive test:** Pass a perturbed `AdmissionWorkspace` inside the packet's stated tolerance into `InitializationSystem::admit` -> returns `Ok(InitialRevision)` with `worst()` within `ErrorScales`. Resume a checkpoint whose SHA-256 the run's archive recorded when the engine wrote it -> the driver resumes.
- **Must-fail negative test:** Perturb one `AdmissionWorkspace` unknown past `ErrorScales` and call `admit` -> returns `Err(InitializationFailure::Inconsistent { .. })`. Hand the driver a checkpoint whose SHA-256 no archived run recorded, with its digests recomputed so that `restore` would take it -> the driver refuses before `Session::resume`. Flip 1 byte in a `Checkpoint` -> `restore` refuses it, as `Corrupt` at most positions and as `UnknownFormat`, `Truncated` or `TrailingContent` in the magic and length bytes (measured: 16 of 753 positions). Doctests that construct or set a `PatientRecord` fail to compile (`E0451`, `E0599`, `crates/ng-record/src/lib.rs:6-122`).
- **Enforcement layer:** Runs now: the Rust type boundary with its doctests, and `admit`'s recheck. To write: the driver's archive records each checkpoint's SHA-256, and the driver checks it before a resume. Whether the contract should say what a host owes at `Session::resume` is a question filed with [foundation 07](../foundation/issues/07-contract.md).

### L2. Conservation by derived two-ended transfers
- **Disposition: Change.** Draft `L2` conflicted with `C2` (`ticket 08`, readings-only recurrent hidden vector with no conserved amounts) and with rate-driven non-material `memories` (`tickets 07, 08`). Further, static `P S = B A` alone does not catch unpaired runtime updates in Python rollouts.
- **Draft rule:** Every conserving model (`conserving == true`: `C1`, `C4a`, `R`, and `5.4` named models) moves amounts exclusively through transfers or reactions compiled from the engine's columns, satisfying integer `P S = B A` at reduction compile time (including integer stoichiometry for reactions) and `|totals(t) - totals(0) - B @ cumulative_extents(t)| <= 64 * 2^-52 * scale` with donor-gated nonnegative outflows at runtime; `memories` evolve only by declared rates, and non-conserving baselines (`C2`) declare `conserving: false`.
- **Positive test:** Compile valid named and `each-row` reductions verifying `P S == B A` in exact integers; roll forward `C1` and `C4a` under random weights for 1,000 steps checking closure within `64 * eps * scale` and nonnegativity.
- **Must-fail negative test:** Drop one active pool from a reduction without marking it `held`, or misclassify a multi-pool reaction column -> `Reduction::compile` refuses (`P S != B A` or unclassified pool); inject an unpaired `+1e-6` delta or nonzero outflow from a zero pool in a synthetic `models.py` forward pass -> `gp.py selftest` fails.
- **Enforcement layer:** Nothing here runs now. To write: `Reduction::compile` in the driver (ticket 05), which the gate's Rust step can run, and the rollout checks beside the models (ticket 08), in ticket 06's environment.

### L3. Readings never feed forward physiological dynamics
- **Disposition: Change.** Blanket wording appeared to ban `5.5` (reads state), `5.6` (reads observations to infer packets), `Rule.react` (reads noisy beats to emit `BoundaryEvent`), and `C2`'s `ReadingsStart`.
- **Draft rule:** Forward physiological stepping (`LearnedRun.advance` and engine `Session::step`) accepts no `Observation`, `ObservationLens`, `ObservationSeed`, or query cadence; `C1`/`C4a`/`R` start only from `NamedStart`, `C2` accepts `ReadingsStart` only at `start()` and feeds only its own noiseless predictions during `advance()`, and `Rule.react` enters only via `enqueue`.
- **Positive test:** Run `C4a` and `C2` over identical events and seeds while querying `beats()` every 1 s vs once at the end and under two `ObservationSeed` values -> final serialized state bytes and `beats()` match bit for bit.
- **Must-fail negative test:** Pass `ReadingsStart` to a named `Model.start` or pass a lens/observation argument to `LearnedRun.advance` -> raises `TypeError`; inject a synthetic model whose `advance` mutates state on `beats()` call count -> fails cadence invariance in `gp.py selftest`.
- **Enforcement layer:** Nothing here runs now. To write: the type boundary of `Model.start` and `LearnedRun.advance` and its tests, beside the models (ticket 08), in ticket 06's environment.

### L4. Seed domain isolation and zero unkeyed step randomness
- **Disposition: Change.** Draft phrasing ("draws nothing of its own") conflicted with keyed stream draws in `5.4`, `ObservationSeed` draws in `5.5`, and posterior proposal draws in `5.6`.
- **Draft rule:** Runtime randomness uses only three separated domains: `PacketSeed` (trait draws and Seam 3 packet proposals), `Seed` (rate forcing and hazard integrals keyed by `(seed, stream_key, event_ordinal)` acting only on rates or event firing, never amounts), and `ObservationSeed` (`5.5` measurement error and artifacts). `5.4` rollouts never use global RNG, dropout, or per-step sampled latents; adding a stream or channel shifts no other draw.
- **Positive test:** Run `LearnedRun` and `Observer` with fixed `(PacketSeed, Seed, ObservationSeed)`, append an unused stream or channel, and re-run -> original stream draws and state bytes are bit-identical; changing `ObservationSeed` leaves `LearnedRun` state bits unchanged.
- **Must-fail negative test:** Pass `Seed` to `Observer::new` -> fails Rust compile (`E0308`, `crates/ng-observe/src/lib.rs:6-10`); inject `random.random()` or an unkeyed per-step latent sample into a synthetic `5.4` forward pass -> fails seed-repeatability in `gp.py selftest`.
- **Enforcement layer:** Runs now: the Rust seed-domain boundary (`DomainSeed<D>`, `crates/ng-observe/src/lib.rs:6-10`). To write: the learned side's repeat and isolation tests, beside the models (ticket 08), in ticket 06's environment. A scan of the model source for unkeyed draws needs only the standard library.

### L5. Bitwise replay across pace, call chunking, and resume
- **Disposition: Change.** `ticket 08` splits integration steps at events and beat edges, whereas caller `advance(until_ns)` calls can land mid-step (`SA`'s caller-clipping bug, `docs/architecture/solver-contract.md:445`). Piecewise event tests also differ from chunking when an added event falls inside an integration step.
- **Draft rule:** `LearnedRun.advance(until_ns)` never clips an integration step at caller `until_ns` (stepping only to the model's fixed/breakpoint grid up to `until_ns` and holding any partial grid remainder), so arbitrary call chunking, pace, and `checkpoint()` + `resume()` yield identical bits within the pinned CPU single-thread float64 runtime (`FROZEN`). Adding a redundant physical event mid-step matches within the scheme's integration tolerance (and bitwise on grid boundaries).
- **Positive test:** Compare `advance(T)`, irregular mid-step splits `advance(t_k)` (e.g. `137_000_000 ns`), and `checkpoint()` + `resume()` mid-run -> serialized state bytes, `totals`, and `beats()` match bit for bit.
- **Must-fail negative test:** Build a synthetic runner that clips RK4 steps at caller `until_ns` or omits recurrent hidden buffers from `LearnedCheckpoint` -> fails arbitrary-split and resume bit-equality tests in `gp.py selftest`.
- **Enforcement layer:** Nothing here runs now. To write: the split and resume tests beside the models (ticket 08), in ticket 06's environment, with the runtime's digest pinned in `FROZEN` (ticket 09).

### L6. Learned dynamics object is a rate per simulated second
- **Disposition: Change.** Draft `L6` gave no boundary for `C2` (`ticket 08` puts `C2` outside `L6`) or non-dynamical models (`5.2`, `5.3`, `5.5`, `5.6`), and omitted the smoothness constraint needed for RK4 order convergence (`C^0` activations drop order).
- **Draft rule:** Every continuous-time dynamics model (`continuous_rate == true`: `C1`, `C4a`, `R`, and hazard-rate modules) learns a `dt`-free rate `(state, traits, drive) -> rate_per_s` with `C^2`-smooth activations (`tanh`/`softplus`) achieving declared integrator convergence order on smooth intervals; `C2`, `5.2`, `5.3`, `5.5`, and `5.6` declare `continuous_rate: false` and stay outside `L6`.
- **Positive test:** Integrate a smooth synthetic `C1` or `C4a` model with zero events at step `h`, `h/2`, `h/4` against `h/16` reference -> observed RK4 convergence order `>= 3.5`.
- **Must-fail negative test:** Construct a synthetic model whose rate reads the step it is called with -> the observed order falls below `3.5` and the test fails. Measured on a scalar example with classical RK4: order `2.9` where the rate scales as `1/h`, and `0.4` to `0.7` where it scales as `h`. Step halving cannot see a constant factor baked into a rate: a model that returns its increment for a `0.1 s` step as the rate still shows order `4.00` (measured). That model has a wrong rate, and only an error against a reference shows it. So a second must-fail plants it and checks that its rollout misses the honest synthetic model's by more than the tolerance.
- **Enforcement layer:** Nothing here runs now. To write: ticket 08's step-halving test and the rollout check above, beside the models, in ticket 06's environment.

### L7. Independent outside check for physiological claims
- **Disposition: Change.** Draft `L7` did not enforce independence from sources already used to author engine laws (`ticket 14` vs `research 13`) or restrict synthetic-packet checks to direction/ordering under SRS rule 16.
- **Draft rule:** Seam 1 (`5.2`, and the `5.3` emulator, whose every candidate the engine runs) and Teacher Data (`5.1`) make no physiological claim and require no outside check. The `5.3` ranking claims something about the engine and nothing about physiology, so it needs none either. Every model claiming physiological behavior (`5.4`, `5.5`, `5.6` clinical scenario claims) names >= 1 clinically reviewed literature source (`outside_checks`) disjoint from `engine_law_sources` and training data, evaluated with `claim_mode: "direction_only"` on `SyntheticFixture` runs and held-out calibration/metrics on `Reviewed` packets. A value fitted with the emulator is a claim about a constant, not a claim by a model. Its check is a sourced response held out of the fit, and its provenance is [ticket 15](issues/15-learned-emulator-for-parameters.md)'s open question, which this draft does not settle.
- **Positive test:** Check an `artifact_manifest.json` for `C4a` (`SyntheticFixture`) carrying `outside_checks` with distinct citation and `claim_mode: "direction_only"`.
- **Must-fail negative test:** Submit a `5.4`, `5.5` or `5.6` artifact manifest with empty `outside_checks`, with a citation present in `engine_law_sources`, or with `claim_mode: "clinical_magnitude"` on a `SyntheticFixture` teacher -> refused by the manifest validator. A `proposal_only` artifact (`5.2`, the `5.3` emulator) passes with none.
- **Enforcement layer:** Nothing here runs now. To write: the artifact manifest's validator, which needs only the standard library and so can run in `gp.py selftest`, and the study's gate (ticket 09).

### L8. Pre-tuning study freeze and single-read held-out isolation
- **Disposition: Change.** Draft `L8` did not enforce partition isolation against `fit`/`call`, `train.py` tuning exclusion (`ticket 09`), or single-evaluation locking (`ticket 12`).
- **Draft rule:** Before any `fit` or `call`, `FROZEN` stores SHA-256 digests of every tracked file under `tools/generative-physiology/` except `FROZEN` and `train.py`. `fit`, `call`, and `evaluate` refuse any tree mismatching `FROZEN`, `gp.py selftest` runs `freeze --check` whenever `FROZEN` exists (plus a temp-tree fixture test before `FROZEN` is committed), each study partition has one reader, and `evaluate` writes a one-shot receipt refusing re-evaluation under the same `FROZEN` digest once `train.py` or weights change. The readers: `fit` reads `train` and `validation_tuning` (ticket 06's 224 training runs and 32 tuning runs); `call` alone reads `validation_call` (ticket 09's 44 validation cases); `evaluate` alone reads `heldout` (ticket 09's 104 runs). `fit` refuses `validation_call` and `heldout`, as ticket 10 already asks ("No fit opens a held-out or validation-case path"), `call` refuses `heldout`, and `fit` and `call` refuse any manifest that shares a `PacketSeed` or a start history with `heldout`. The tuning runs and the validation cases share ticket 06's 4 validation start histories, so the partition name is what keeps the cases out of a fit.
- **Positive test:** Verify `gp.py freeze --check` passes on an unaltered frozen fixture tree, `fit` accepts `train` and `validation_tuning` manifests, `call` accepts a `validation_call` manifest, and `evaluate` writes one valid receipt.
- **Must-fail negative test:** Alter 1 byte of a frozen file (`spec.py` or `features.py`) without updating `FROZEN` -> `freeze --check` fails naming that file; pass a `validation_call` or `heldout` manifest to `fit`, or a `heldout` manifest to `call` -> refused (`PartitionError`); invoke `evaluate` a second time after editing `train.py` under the same `FROZEN` digest -> refused (`AlreadyEvaluatedForFrozenDigest`).
- **Enforcement layer:** Nothing here runs now. To write: ticket 09's `FROZEN` check, which needs only the standard library and can run in `gp.py selftest` (`tools/gate/paths.toml:14-16`), and the partition and receipt guards in `fit`, `call` and `evaluate` (tickets 10 to 12).

### L9. Complete accounting of faults and admission refusals
- **Disposition: Change.** `tools/generative-physiology/driver/src/teacher.rs:741-749` and `main.rs:213-215` show that an `InitializationFailure` leaves `gp-driver` through a handled error: it exits `1` and archives no outcome. Measured on an error returned after admission: only `<id>.partial-<pid>/` is left, where a fault leaves `<id>.fault/` and exits `3`. The driver admits one fixed packet today (`teacher.rs:739`), so no input makes its admission refuse. That matters once packets vary, because `5.2` and `5.3` need every refusal counted (`L9`).
- **Draft rule:** Every planned run in a dataset ends in one closed outcome: `complete`, `fault` (any kind the driver writes: an engine fault, `MemoryCap` or `Protocol`, `tools/generative-physiology/driver/src/archive.rs:224-233`), or `refused` (`AdmissionError` or `InitializationFailure`). `gp-driver` persists `.fault/` and `.refused/` directories atomically; `dataset_manifest.json` lists every planned `spec_id` with exact counts (`total_planned == complete + fault + refused`). Exporters exclude non-complete trajectories from dynamics fits while retaining all failures in counts and feasibility surfaces.
- **Positive test:** Check a mixed synthetic corpus (`complete`, planted `MemoryCap` `.fault`, planted `Inconsistent` `.refused`) -> `manifest.py` verifies `total_planned == complete + fault + refused` and digest match.
- **Must-fail negative test:** Delete one `.fault` or `.refused` directory on disk, omit one `spec_id` from `entries`, or alter `counts` in `dataset_manifest.json` -> manifest validator and `gp.py export` refuse (`ManifestMismatch`).
- **Enforcement layer:** Runs now: the driver's fault archive, for a run. To write: the `.refused/` archive in the driver, and the dataset manifest's validator, which needs only the standard library and can run in `gp.py selftest`.

### L10. Artifact provenance manifest and load-mismatch refusal

## 4. Two architectural shapes compared

### 4.1 `L9`/`L10` dataset and artifact manifest layout

- **Shape A (Canonical line-text `gp-manifest 1` / `gp-artifact 1`):** Flat sorted key-value line records extending `summary.txt` (`tools/generative-physiology/driver/src/archive.rs:359-410`) and `catalogue.txt` (`capture.py:98`), parsed via `_Lines` without JSON nesting. Pros: zero nested parser ambiguity and matches existing driver text formats. Cons: awkward for lists (`entries`, `outside_checks`, `feature_accounting`) and forces custom parser updates whenever a field is added.
- **Shape B (Canonical JSON `dataset_manifest.json` and `artifact_manifest.json`):** Sorted-key compact JSON (`json.dumps(..., sort_keys=True, separators=(",", ":"))`) with full-payload SHA-256 self-digest (omitting only the self-digest key), extending `ticket 05`'s `reduction-*.json` pattern (`Python 3.11` stdlib `json` only).

**Exact required fields (Shape B):**
- **`dataset_manifest.json`:** `schema_version` (`1`), `partition` (`train | validation_tuning | validation_call | heldout | replay | library | audit`, where `validation_tuning` is ticket 06's `VALIDATION`, `validation_call` is ticket 09's validation cases, and `replay` is ticket 06's `REPLAY`), `origin_policy` (`engine_teacher | authored_scenario_eval`), `source_commit`, `crates_tree_digest`, `model_hash`, `frozen_digest` (`string | null`, required non-null for study partitions), `counts` (`{total_planned, complete, fault, refused}`), `packet_hashes_digest` (SHA-256 of sorted unique `packet_hash` hex strings), `entries` (sorted by `spec_id`, each `{spec_id, origin, packet_kind, packet_hash, resolution_digest, run_identity, outcome, detail, summary_sha256, parent_spec_id}` where `origin` is `engine_teacher | authored_scenario_eval`, `packet_hash` is the pre-admission hash, present even when `outcome == "refused"`, and `run_identity` is `null` iff `outcome == "refused"`), and `manifest_digest`. A host reads the pre-admission hash through `packet.anchors().packet()` (`crates/ng-contract/src/packet.rs:254`, `crates/ng-contract/src/provenance.rs:93`), because `ParameterPacket::hash` is private (`packet.rs:424`). It is not the hash `summary.txt` records, which is the admitted one (`tools/generative-physiology/driver/src/teacher.rs:757`).
- **`artifact_manifest.json`:** `schema_version` (`1`), `artifact_kind` (`start_proposer | emulator_stage_a | emulator_stage_b | gp_model | observer | chart_inference`), `family` (`nearest | continuation | linear_map | gp_ard | neural_emulator | C1 | C2 | C4a | R | instrument | qualitative | npe | fmpe`), `claim_label` (`proposal_only | validated | approximate | untested`), `claim_level` (`1` to `5` from ticket 01's section 6, `null` when `proposal_only`), `conserving` (`bool`), `continuous_rate` (`bool`), `engine_commit`, `crates_tree_digest`, `model_hash`, `dataset_manifest_digest`, `packet_hashes_digest`, `reduction_digest` (`string | null`, required if `conserving`), `frozen_digest` (`string | null`), `train_script_sha256`, `training_seed`, `runtime_env_digest`, `weights_sha256`, `outside_checks` (`[{citation, source_set_tag, claim_mode}]`), `feature_accounting` (`null` unless `observer`), and `artifact_digest`.
- **Digest chain and refusal conditions:** `manifest_digest` hashes the full sorted-key compact JSON with `manifest_digest` omitted (sealing `partition`, `origin_policy`, `model_hash`, `frozen_digest`, `counts`, `packet_hashes_digest`, and all `entries`), and each entry's `summary_sha256` binds `summary.txt` (or `refusal.txt`) on disk. `artifact_digest` hashes the full sorted-key compact JSON with `artifact_digest` omitted (sealing `weights_sha256`, `dataset_manifest_digest`, `packet_hashes_digest`, `model_hash`, `reduction_digest`, `frozen_digest`, `outside_checks`, `feature_accounting`, and `claim_label`). Validators refuse: missing/duplicate `spec_id`; `total_planned != complete + fault + refused`; any `.fault`/`.refused` directory omitted from `entries`; `summary_sha256`, `manifest_digest`, `artifact_digest`, or `weights_sha256` mismatch; `origin != "engine_teacher"` when `origin_policy == "engine_teacher"` or on training/library manifests; `validation_call` or `heldout` passed to `fit`, or `heldout` passed to `call`; `model_hash`/`reduction_digest` mismatch on `load()`; `frozen_digest` null or mismatching active `FROZEN` (when `FROZEN` exists, or whenever `frozen_digest` is set); empty `outside_checks` when `claim_label != "proposal_only"`.
- **Model default:** **Shape B** (`dataset_manifest.json` / `artifact_manifest.json`). Tradeoff: relies on canonical `sort_keys=True` JSON serialization in Python in exchange for structured nested checks (`counts`, `outside_checks`, `feature_accounting`) consistent with `ticket 05`'s `reduction-*.json`.
- **One-line alternative:** Shape A (`gp-manifest 1` / `gp-artifact 1` line-text files) if `gp-driver` must parse or emit manifests in Rust without adding a JSON parser crate.

### 4.2 Rule enforcement layering across `tools/generative-physiology/`

- **Shape A (Centralized CLI gate `rules_gate.py`):** One standalone Python gate inspects directories, `FROZEN`, and manifests around CLI entrypoints in `gp.py`, keeping `models.py` and `study` modules unaware of rules `L1` to `L14`. Pros: one inspection file. Cons: duplicates parsing/state knowledge and is bypassed whenever Python code imports `models.load()` or `Study` directly.
- **Shape B (Boundary-embedded four-layer enforcement):** Each rule lives at the constructor/loader/API boundary that owns its state:
  1. **Rust types and `gp-driver` (`10-rust`):** `L1` (`PatientRecord`, `InitialRevision`, `admit`), `L4`/`L13` (`DomainSeed<D>`, `ObservedValue`), `L2` (`Reduction::compile` `P S = B A`), `L9` (atomic `.fault` / `.refused` directories).
  2. **Manifest and study loaders (`manifest.py`, `freeze.py`, `models.load()`, `Study.frozen()`):** `L7`, `L8` (`FROZEN`, one reader for each study partition, single `eval_receipt`), `L9`, `L10`, `L12`, `L13` (`feature_accounting`), `L14` (`study.call`).
  3. **Model runtime APIs (`models.py`, `LearnedRun`):** `L2` (`totals += B @ extents`), `L3` (`advance` takes no readings/lens), `L4` (keyed RNG only), `L5` (grid-aligned `advance`, no caller clipping), `L6` (`dt`-free smooth rates), `L11` (read-only support excursion, `ModelFault` on negative step, zero clamping).
  4. **Two places a test can run.** `gp.py selftest` runs under `tools/verify.d/10-rust.sh:60` as `python3 -I`, on the standard library alone (`tools/generative-physiology/gp.py:7`). It can hold the tests that need no array library: the manifest validators (`L7`, `L9`, `L10`, `L12`, `L13`), `freeze --check` whenever `FROZEN` is present (`L8`), and `call` on synthetic scores (`L14`). Every test that runs a model (`L2` to `L6`, `L11`, and the load guard of `L10`) runs where tickets 06 and 08 put it: in the pinned numpy and PyTorch environment on the heavy-run machine. No gate file names either library. Whether the gate's machines should hold that environment is the developer reviewer's question.
- **Model default:** **Shape B** (boundary-embedded four-layer enforcement). Tradeoff: rules distribute across Rust and Python modules (requiring this draft's table), in exchange for parse-once boundaries and fast-gate feedback via `tools/gate/paths.toml:14-16` for the tests that need only the standard library.
- **One-line alternative:** Shape A (centralized `rules_gate.py` CLI wrapper), used only if unreviewed external scripts invoke `gp-driver` directly without importing `Study` or `models`.
